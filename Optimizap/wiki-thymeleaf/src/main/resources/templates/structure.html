Estructura y Arquitectura del Proyecto

Inicio > Estructura y Arquitectura

El proyecto Optimizapp está organizado siguiendo una arquitectura por capas, con el objetivo de mantener una separación clara entre la presentación, la lógica de negocio, el acceso a datos y la persistencia. Esta estructura facilita el mantenimiento del sistema, la escalabilidad y el trabajo colaborativo entre los integrantes del equipo.

Arquitectura general

La solución está construida sobre Spring Boot y aplica el patrón MVC (Modelo - Vista - Controlador). A nivel general, la arquitectura se divide en:

  • Capa de presentación: compuesta por controladores y vistas, encargadas de recibir las solicitudes del usuario y mostrar la información.
  • Capa de servicios: contiene la lógica de negocio del sistema y coordina las operaciones principales.
  • Capa de acceso a datos: implementada mediante repositorios JPA para interactuar con la base de datos.
  • Capa de persistencia: soportada en una base de datos PostgreSQL donde se almacena la información del sistema.

Estructura del backend

En el backend, el proyecto está organizado en paquetes que responden a las responsabilidades principales del sistema. Esta distribución permite que cada componente tenga una función clara dentro de la aplicación.

  • entities: contiene las clases del dominio, como usuarios, empresas y procesos.
  • repositories: agrupa los repositorios JPA encargados de la comunicación con la base de datos.
  • services: incluye la lógica de negocio y las reglas del sistema.
  • controllers: expone los endpoints o controla la navegación entre vistas.
  • dtos: define los objetos de transferencia de datos utilizados para desacoplar la capa interna de la externa.
  • exceptions: centraliza el manejo de errores y excepciones del sistema.
  • config: reúne configuraciones generales del proyecto, como beans, seguridad o mapeadores.

Relación entre componentes

El flujo general del sistema funciona de la siguiente manera: el usuario interactúa con la interfaz, el controlador recibe la solicitud, delega la operación al servicio correspondiente, el servicio consulta o actualiza la información mediante los repositorios y finalmente se devuelve una respuesta o vista al usuario. Este diseño mejora la organización del código y hace más sencilla la incorporación de nuevas funcionalidades.

Tecnologías principales

  • Java y Spring Boot: base del desarrollo backend.
  • Spring Data JPA: manejo de persistencia y repositorios.
  • PostgreSQL: sistema gestor de base de datos.
  • Thymeleaf: motor de plantillas para la construcción de las vistas web.
  • Lombok: reducción de código repetitivo en entidades y clases de soporte.
  • ModelMapper: conversión entre entidades y DTOs.
  • Docker y Kubernetes: apoyo al despliegue y ejecución del sistema en contenedores.
  • GitHub: control de versiones y trabajo colaborativo.

Aislamiento por empresa

Uno de los principios del proyecto es el enfoque multiempresa. Esto significa que cada empresa administra sus usuarios y sus procesos de manera aislada, evitando que la información de una organización interfiera con la de otra. De esta manera, el sistema mantiene independencia lógica entre compañías y favorece una administración segura y ordenada de los procesos empresariales.

Conclusión

En conjunto, la arquitectura del proyecto permite una solución ordenada, modular y mantenible. La separación por capas, el uso de buenas prácticas de desarrollo y la incorporación de tecnologías como Spring Boot, JPA, PostgreSQL y Thymeleaf fortalecen la base técnica del sistema y facilitan su evolución durante las siguientes entregas del proyecto.
